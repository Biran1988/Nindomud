# Nindo_mud audit — November 13, 2026

Baseline: main at a0c8e9f (Update Genin cap regression to level 35).

## Changes

- Fixed an unterminated module docstring in data_headbands.py. It prevented
  normal startup and caused 186 test-import errors in the initial run.
  Replaced stale explanatory text with a description of the actual item model.
- Kept trade proposals pending until the invited player accepts. Prevented a
  new proposal from overwriting either participant's pending trade.
- Revalidated consent, session ownership, room, available ryo and item counts
  immediately before transferring a trade. A spent offer cannot create a
  negative balance; an unavailable item cannot cause a partial transfer.
  Both participants now receive the actual failure reason.
- Consolidated player, account and ten shared-registry JSON writes through
  one atomic-write helper. Serialization completes before opening a temporary
  file; successful writes are flushed before replacement. Failed serialization,
  flush or replacement preserves the previous save. The existing world-save
  backup and locking mechanism remains separate.
- Updated stale rank-cap and headband tests to current progression, corrected
  obsolete promotion scenarios, restored XP overflow help, and closed a leaked
  test file handle. No balance or rank redesign was introduced.

The legacy diagnostic continued after failures in one process to expose the
rest of the suite. Those 162 successful calls are not 162 isolated feature
certifications; shared state and earlier failures can affect later scenarios.
The normal smoke script remains failing. Some confirmed stale assumptions
include removed ranks and NPCs, old tool-tier counts, practice restrictions,
and outdated unlock levels. Many later scenarios fail during their character
setup. Remaining failures need isolated reproduction before classification as
game bugs versus obsolete fixtures; none were marked passing or suppressed.

This is a substantial automated audit, not proof that every feature and every
multiplayer interaction is correct. It does not certify production-world data,
long-running economy balance, load capacity, Windows execution, or every
class/clan/jutsu combination. The live server was not accessed or modified.

## Recommended next upgrades

1. Split the 18,000-line legacy smoke script into isolated scenarios with
   temporary save directories, explicit fixtures and cleanup. Remove import-time
   deletion/reconfiguration of test storage. Keep current assertions for
   supported behavior and replace obsolete scenarios with tested equivalents.
2. Add a feature-to-test coverage matrix and socket-driven multiplayer journeys
   covering trading, combat, exams, crafting, boats, disconnect/reconnect and
   server restart. Measure coverage to identify unexecuted branches.
3. Make releases depend on a maintained end-to-end gate. The current publishing
   workflow depends on the unit/package job while the separate smoke job can
   fail; do not silently treat that as a clean release.
4. Add a durable transaction journal for multi-player trades and auctions.
   Per-file atomic writes prevent truncation, but cannot make two independently
   saved player balances a single crash-atomic transaction. A crash between
   player saves remains a separate durability risk.
5. Gradually extract commands.py into cohesive command modules with typed
   boundaries. Centralize rank metadata to reduce drift between gameplay,
   headbands, help and fixtures; avoid another large rewrite without tests.
6. Extend save fault-injection tests to disk exhaustion, abrupt shutdown,
   backups and recovery. Audit other modules that write their own JSON directly.
7. Add deterministic long-duration simulations for resource upkeep, timers,
   economic inflation and concurrent player activity, plus profiling of pulse
   latency under load.

Release archive excludes runtime data. Existing saved configuration and player
files must remain in place when deploying this code update.
